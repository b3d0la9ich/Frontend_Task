# Frontend_Task

Я создал небольшое веб-приложение для просмотра и управления проектами.

Проект выполнен в рамках тестового задания с использованием Next.js, React, TypeScript и Tailwind CSS.

## Демонстрация

Развёрнутая версия приложения:

`https://frontend-task-rosy-one.vercel.app`

Публичный GitHub-репозиторий:

`https://github.com/b3d0la9ich/Frontend_Task`

## Технологии

- Next.js
- React
- TypeScript
- Tailwind CSS
- Zod
- Next.js App Router
- React Context

## Возможности

Приложение позволяет:

- просматривать список проектов;
- просматривать подробную информацию о проекте;
- создавать новые проекты;
- искать проекты по названию;
- фильтровать проекты по статусу;
- сортировать проекты по дате создания;
- валидировать данные формы;
- отображать состояния загрузки, ошибки и отсутствия данных;
- работать с интерфейсом с клавиатуры;
- корректно отображаться на разных размерах экрана.

## Архитектура проекта

Проект построен с использованием Next.js App Router.

Приложение разделено на страницы, переиспользуемые компоненты, типы, схему валидации и локальные данные.

## Основные архитектурные решения

### Страницы и маршрутизация

Для маршрутизации используется Next.js App Router.

`/projects` — страница со списком всех проектов.

`/projects/[id]` — динамический маршрут для просмотра отдельного проекта.

`/projects/new` — страница создания нового проекта.

Корневой маршрут `/` перенаправляет пользователя на `/projects`.

### Компоненты

`ProjectCard` отвечает за отображение карточки отдельного проекта.

`ProjectList` отображает список карточек проектов и состояние, когда проекты не найдены.

`ProjectsClient` содержит клиентскую логику поиска, фильтрации и сортировки проектов.

`ProjectDetails` отображает подробную информацию о выбранном проекте.

`ProjectForm` содержит форму создания проекта и обработку валидации.

`ProjectProvider` предоставляет общее состояние проектов через React Context.

### Server и Client Components

Server Components используются по умолчанию в тех местах, где не требуется клиентская интерактивность.

Client Components используются для частей приложения, которым необходимы React state, обработчики событий, Context или другая логика на стороне браузера.

Такой подход позволяет не переносить всё приложение на клиентскую сторону без необходимости.

### Валидация

Для валидации формы создания проекта используется Zod.

Схема валидации вынесена в отдельный файл:

```text
lib/validation/project.ts
```

Обязательные поля проверяются перед созданием проекта. При ошибке пользователь получает соответствующее сообщение рядом с полем формы.

### Управление состоянием

Начальные данные проектов находятся в:

```text
data/projects.ts
```

Для управления списком проектов во время работы приложения используется React Context.

После создания новый проект сразу добавляется в список проектов.

Настоящий backend и база данных не используются, поэтому созданные пользователем проекты не сохраняются после полной перезагрузки страницы.

## Состояния интерфейса

В приложении реализованы:

- состояние загрузки;
- skeleton-загрузка;
- состояние отсутствия результатов поиска или фильтрации;
- страница для несуществующего проекта;
- обработка ошибок;
- состояние отправки формы.

Во время загрузки списка проектов пользователю отображается skeleton-интерфейс вместо обычного текста загрузки.

## Доступность

В интерфейсе используются семантические HTML-элементы:

- `button`;
- `input`;
- `textarea`;
- `select`;
- `label`;
- ссылки.

Основные интерактивные элементы доступны с клавиатуры.

Поддерживается стандартная навигация с помощью `Tab`, `Shift + Tab`, `Enter` и других стандартных клавиш браузера.

## Хранение данных

В проекте не используется настоящий backend или база данных.

Начальные проекты хранятся локально, а созданные пользователем проекты добавляются в React Context.

Поэтому новые проекты доступны в рамках текущей сессии приложения, но после полной перезагрузки страницы состояние сбрасывается.

Такой подход выбран в соответствии с условиями задания, допускающими использование локального состояния.
